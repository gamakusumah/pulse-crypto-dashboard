# Internationalization (i18n)

The app supports **English (US)** and **Indonesian**, switchable at runtime
via the language toggle in the header, with the choice persisted across
visits.

## Stack

- [`i18next`](https://www.i18next.com/) — translation engine
- [`react-i18next`](https://react.i18next.com/) — React bindings (`useTranslation()`)
- Translations are bundled at build time as JSON — no network fetch, no
  lazy-loading backend. With only two languages, that added complexity
  isn't worth it; both resource files together are a few KB.

## Files

```
src/
  constants/i18n.ts              # LANGUAGE_STORAGE_KEY, LANGUAGES, SUPPORTED_LANGUAGES
  lib/i18n.ts                    # i18next.init(), language detection, persistence
  locales/
    en/translation.json          # English (US) strings
    id/translation.json          # Indonesian strings
  components/common/
    LanguageToggle.tsx           # Header toggle button
```

## How Language Selection Works

1. On load, `src/lib/i18n.ts` determines the initial language in this order:
   1. A previously saved choice in `localStorage` (key: `pulse-ui-language`)
   2. The browser's language (`navigator.language`), if it's one of the
      supported languages
   3. Falls back to English
2. `main.tsx` does `await i18nReady` **before** calling `createRoot(...).render(...)`,
   so there's no flash of the wrong language or untranslated keys on first
   paint.
3. `LanguageToggle` calls `i18n.changeLanguage(...)`, which:
   - Re-renders every component using `useTranslation()`
   - Fires `i18n.on('languageChanged', ...)`, which updates
     `document.documentElement.lang` and persists the choice to
     `localStorage`

This mirrors the existing `ThemeProvider`/`ThemeToggle` pattern (same
persistence-key + toggle-button shape), so the two settings behave
consistently from the user's perspective.

## Using Translations in a Component

```tsx
import { useTranslation } from 'react-i18next';

function Example() {
  const { t } = useTranslation();
  return <h2>{t('home.categoryMarket.title')}</h2>;
}
```

Interpolation:

```tsx
t('home.table.page', { page }); // "Page 3" / "Halaman 3"
```

## What Is — and Isn't — Translated

**Translated:** all UI chrome — headings, labels, button text, aria-labels,
empty/error state copy, table headers, pagination text.

**Not translated (by design):** content that comes from an external source
rather than being authored UI copy — coin names/symbols, category names,
and news/insight article text all come from CoinGecko (or its mocked
stand-in, see [API.md](./API.md)). A real API wouldn't return these in the
viewer's UI language either, so translating them client-side would be
misleading. If localized market content becomes available from the data
source in the future, it can be passed straight through without changing
this i18n layer.

## Locale-Aware Formatting

- `formatDate()` (`src/utils/formatDate.ts`) uses `Intl.RelativeTimeFormat(i18n.language, ...)`
  and `Intl.DateTimeFormat(i18n.language, ...)`, so "2 hours ago" becomes
  "2 jam yang lalu" automatically when the language is Indonesian.
  Components that render a relative date (`NewsCard`, `InsightCard`) call
  `useTranslation()` even without using `t()` directly — this subscribes
  them to language-change re-renders so the relative label updates
  immediately when the toggle is used.
- `formatCurrency()`, `formatNumber()`, and `formatPercentage()` intentionally
  keep `en-US` number formatting (decimal points, comma thousands
  separators) regardless of the UI language. This matches how financial/
  trading platforms conventionally present figures — consistently,
  independent of the viewer's locale — rather than reformatting numbers
  in a way that could make market data harder to compare or copy.

## Adding a New Translation Key

1. Add the key to **both** `src/locales/en/translation.json` and
   `src/locales/id/translation.json` — keep the same key path in both
   files.
2. Use it via `t('your.new.key')`.

## Adding a Third Language

1. Add `src/locales/<code>/translation.json` with every key from
   `en/translation.json` translated.
2. Add the language to `LANGUAGES` and `SUPPORTED_LANGUAGES` in
   `src/constants/i18n.ts`.
3. Register the resource in the `resources` object in `src/lib/i18n.ts`.
4. `LanguageToggle` currently cycles between exactly two languages
   (`NEXT_LANGUAGE` maps each language straight to the other). With three
   or more, replace it with a dropdown/select instead of a toggle button.
